## 3. 단계별 실험 내역

### 3.1 합성 근거 후보 생성과 데이터 격리

첫 단계에서는 2,000개 학습 글과 400개 검증 글 각각에 대해 세 개의 근거 후보를
생성했다. 생성 모델은 `gpt-5.6-terra`였으며, 후보 형식은 내용·조직·표현의 세 축을
포함하는 구조화된 근거였다.

- 학습 후보: 2,000개 글 × 3개 = 6,000개
- 검증 후보: 400개 글 × 3개 = 1,200개
- 학습과 검증 산출물은 분리하여 제한·비추적 경로에 저장
- 원문, 식별자, 개별 근거 및 개별 점수는 Git에 기록하지 않음
- 검증 후보는 SFT, 선호쌍 생성 또는 보상 학습에 사용하지 않음

초기 로컬 judge 준비 과정에서는 런타임과 응답 형식 문제가 여러 차례 발생했다.
실패 산출물은 덮어쓰지 않고 보존했으며, 모델 학습은 데이터·스키마·실행 환경의
필수 게이트가 통과한 뒤에만 진행했다.

근거: [OpenAI 합성 피드백 실행 기록](../../experiment_records/openai_feedback_batch_20260719_001.md)

### 3.2 세 기반 모델의 근거 생성 SFT

검증된 6,000개 학습 후보로 세 공개 디코더를 LoRA SFT했다.

- `skt/A.X-4.0-Light`
- `microsoft/Phi-4-mini-instruct`
- `K-intelligence/Midm-2.0-Base-Instruct`

각 기반 모델에 대해 다음 네 작업을 별도로 학습하여 총 12개 SFT를 수행했다.

1. 내용·조직·표현 근거를 한 번에 생성하는 bundle 모델
2. 내용 전용 모델
3. 조직 전용 모델
4. 표현 전용 모델

SFT 입력에는 글쓰기 문항과 학생 글만 사용하고 정답 점수나 합성 후보의 점수는
노출하지 않았다. 주요 학습 설정은 LoRA `r=32`, `alpha=64`, 최대 길이 3,072,
학습률 `2e-5`, 2 epoch이었다. 전체 학습은 TRL `SFTTrainer`로 수행했다.

초기 BF16 학습에서는 비유한 gradient가 발생하여 해당 실행을 제외했다. 데이터,
목적함수, 학습률, epoch, seed와 선택 규칙은 유지하고 디코더 기반·LoRA·헤드의
연산 정밀도만 float32로 바꾸어 수치 안정성을 회복했다. 모든 12개 최종 SFT는
유한한 학습 지표와 완전한 어댑터를 남겼다.

근거: [API 근거 SFT 및 점수 회귀 실험](../../experiment_records/api_rationale_sft_and_score_regression_v1_20260721_008.md)

### 3.3 점수 비공개 RLAIF-GRPO

SFT 어댑터를 시작점으로 삼아 점수 비공개 RLAIF-GRPO를 수행했다. 정책은 한 글에
대해 네 개의 근거를 생성하고, `Qwen3.6-35B-A3B-FP8` judge가 근거 품질을 1~5점으로
평가했다. judge는 사람 점수나 글의 정답 점수를 받지 않았다.

비교한 보상 방식은 다음과 같다.

- `all5`: 고정된 다섯 가지 judge 프롬프트의 평가를 평균
- `random1`: 각 생성 결과에 다섯 프롬프트 중 하나를 결정적으로 배정

최종 v8 계약의 핵심 설정은 다음과 같다.

- 학습 모집단: 1,920개 train-only 그룹
- 그룹당 생성 수: 4
- 업데이트: 480
- 학습률: `1e-6`
- KL 계수 `beta`: `0.02`
- 손실: `dr_grpo`
- rollout sampling: temperature `0.7`, top-p `0.95`
- 근거 축별 길이 제한: 192자
- 원 점수와 후보 점수의 정책 프롬프트 노출: 없음

A.X bundle의 `random1` 모델은 고정 judge 평가에서 SFT macro 3.766183보다 높은
4.187033을 기록했다. 이후 근거-점수 결합 실험에서는 judge 순위 2위였던 이 모델의
근거가 가장 좋은 점수 회귀 결과를 만들었으므로 `rank2_ax4_random1`이라는 이름으로
선택되었다.

근거: [RLAIF-GRPO v8 기록](../../experiment_records/rlaif_grpo_prompt_ensemble_v8_20260722_022.md)

### 3.4 상위 근거 모델과 점수 회귀기의 결합

고정 judge 기준 상위 세 bundle 근거 모델을 각각 독립적으로 사용하여 점수 회귀기를
학습했다.

1. Midm `random1`
2. A.X `random1`
3. A.X `all5`

이 단계에서는 세 근거를 합치거나 평균하지 않았다. 각 근거 출처마다 별도의
Qwen2.5-7B 점수 회귀기를 학습하여 내용·조직·표현만 예측했다. A.X `random1`이
세 축 macro RMSE 0.663171로 가장 낮아 이후 Qwen3-Embedding 실험의 고정 근거
출처로 선택되었다.

근거: [상위 3개 근거/인코더 실험](../../experiment_records/rlaif_top3_encoder_v1_20260725_001.md)

### 3.5 Qwen3-Embedding 초기화 비교

점수 모델 기반을 `Qwen/Qwen3-Embedding-8B`로 바꾸고 다음 두 초기화를 동일한
조건에서 비교했다.

1. 공개 Qwen3-Embedding 체크포인트에서 직접 시작
2. 48,016개 AI-Hub 인간 피드백 레코드로 학습된 LoRA·회귀 헤드 상태에서 시작

두 모델 모두 2,000개 학습 글과 고정된 A.X `random1` 근거를 입력으로 받았다.
AI-Hub 상태의 기존 네 출력 중 `average` 행은 제거하고 내용·조직·표현 세 축만
계속 학습했다.

공개 체크포인트 직접 초기화는 이 고정 스케줄에서 macro RMSE 2.062436으로
유효한 점수 모델을 만들지 못했다. AI-Hub warm start는 macro RMSE 0.591186을
기록하여 명확히 우수했고 이후 R0 계보의 초기화로 채택되었다.

근거: [Qwen3-Embedding 초기화 비교](../../experiment_records/rlaif_qwen3_embedding_comparison_v1_20260726_001.md)

### 3.6 epoch sweep과 R0 앙상블

AI-Hub warm start 모델을 12 epoch 학습하고 각 epoch의 LoRA와 3출력 회귀 헤드를
저장했다. 단일 체크포인트 선택에서는 epoch 3이 macro RMSE 0.569245로 가장
좋았지만, 초기 네 epoch이 축마다 서로 다른 장점을 보였다.

사전에 정의한 두 결합 방법을 비교했다.

- P1~4: epoch 1~4가 낸 연속 예측을 균등 평균
- S1~4: epoch 1~4의 부동소수점 LoRA·헤드 상태를 평균한 뒤 한 번 예측

최종적으로 P1~4 예측 앙상블이 macro RMSE 0.558294, macro Spearman 0.644196으로
가장 좋았다. 추가 입력 지시문, trait별 모델, 다중 근거, full-parameter AI-Hub
초기화 등의 고정 ablation도 이 결과를 넘지 못했다. 따라서 네 체크포인트의
가중치 평균이 아니라 **네 독립 예측의 산술 평균**을 R0 점수 모델로 확정했다.

### 3.7 예측 점수 기반 최종 근거 DPO

제출 결과에는 점수뿐 아니라 한국어 근거도 필요했다. 점수 예측에 사용한 짧은
score-blind 근거를 그대로 노출하는 대신, R0이 산출한 정수 점수를 조건으로 최종
근거를 다시 생성하는 A.X DPO 모델을 학습했다.

- 6,000개 train-only 그룹에서 후보 24,000개 생성
- 고정 Qwen Q4 judge로 후보 평가
- 전체 동점 그룹 3,230개 제외
- 최소 1점 차이가 있는 선호쌍 2,770개 유지
- TRL `DPOTrainer`, 1 epoch, 174 updates
- validation은 선호쌍 생성이나 DPO 학습에 사용하지 않음

검증 비교에서 DPO 모델은 macro 4.9877083/5를 기록해 수치상 최종 근거 모델로
선택되었다. 다만 SFT 대비 차이는 작고 sign test의 전통적 0.05 기준을 통과하지
못했으므로, 이를 강한 품질 개선 증거로 과장하지 않는다.

### 3.8 제출 이미지 구성과 검증

최종 R0 파이프라인은 두 공개 기반 모델과 LoRA/헤드 산출물을 하나의 오프라인
Docker 이미지에 포함했다.

- score base: Qwen3-Embedding-8B
- score members: epoch 1~4 LoRA와 회귀 헤드
- rationale base: A.X-4.0-Light
- 첫 근거: `rank2_ax4_random1`
- 최종 근거: emitted-score-conditioned DPO adapter

모델을 포함한 이미지를 명령행 인자 없이 GPU0에서 실행하고 `/health`, `/v1/models`,
`/v1/chat/completions`를 확인했다. 짧은 입력과 2,048 토큰 점수 입력 한도를 넘기는
긴 합성 입력이 모두 strict JSON으로 완료되었다. 검증된 이미지를 Docker Hub에
푸시한 뒤 익명 토큰으로 manifest, config 및 36개 layer blob 접근을 확인했다.

근거: [R0 Docker/Hugging Face 제출 준비 기록](../../experiment_records/r0_ensemble_docker_hf_preparation_20260731_001.md)

## 4. 최종 선택 논리

첫 번째 제출은 다음 우선순위로 결정되었다.

1. 세 축 점수의 연속 macro RMSE를 가장 우선한다.
2. RMSE가 같으면 macro Spearman을 확인한다.
3. 점수 선택과 최종 근거 품질 선택을 분리한다.
4. 검증 결과를 본 뒤 가중치, threshold 또는 calibration을 다시 맞추지 않는다.
5. 실패한 수치·런타임 실험은 삭제하지 않고 음성 결과로 남긴다.
6. 최종 이미지가 오프라인, 단일 GPU, OpenAI 호환 API 계약을 만족해야 한다.

이 원칙에 따라 점수에는 R0 epoch 1~4 예측 앙상블을, 최종 설명에는 A.X DPO
어댑터를 사용했다.

## 5. 해석 시 주의점

- 400개 검증 글은 여러 개발 단계에서 이미 사용되었으므로 모든 검증 지표는
  개발 증거이지 untouched hidden-test 추정치가 아니다.
- 근거 모델 평가는 주로 LLM-as-judge에 의존하므로 인간 평가와 동일하지 않다.
- 점수 앙상블의 RMSE와 최종 DPO 근거의 judge 점수는 서로 다른 평가이며, 결합된
  전체 파이프라인의 단일 hidden-test 지표가 아니다.
- `20260731-002`의 파서 보강은 모델·프롬프트·점수 앙상블을 바꾸지 않았다.
- `20260812-003`은 최종 근거 모델이 바뀐 후속 구성이므로 이 문서의 첫 제출
  방법론에 포함하지 않는다.
