# 첫 번째 제출 모델의 최종 방법론

## 1. 방법론 개요

첫 번째 제출 모델은 한국어 글을 바로 정수 점수로 분류하는 단일 모델이 아니다.
점수 비공개 근거 생성, 근거 조건부 점수 회귀, 다중 체크포인트 예측 앙상블,
예측 점수 기반 최종 근거 생성을 순서대로 수행하는 파이프라인이다.

```text
글쓰기 문항 + 학생 글
    │
    ▼
A.X-4.0-Light + score-blind GRPO LoRA
    │  내용·조직·표현의 내부 평가 근거
    ▼
Qwen3-Embedding-8B + epoch 1~4 LoRA/회귀 헤드
    │  네 개의 연속 3축 예측
    ▼
축별 균등 평균 → [1, 5] clipping → half-up 정수화
    │  최종 내용·조직·표현 점수
    ▼
A.X-4.0-Light + emitted-score-conditioned DPO LoRA
    │  제출용 한국어 근거
    ▼
내용·조직·표현별 score/rationale JSON
```

## 2. 고정 모델 구성

| 역할 | 모델·산출물 | 고정 식별자 |
| --- | --- | --- |
| 근거 기반 모델 | `skt/A.X-4.0-Light` | revision `ba21c20ea1b31ded1ec3e2fb432335077dc4be98` |
| 내부 score-blind 근거 | A.X `rank2_ax4_random1` GRPO LoRA | adapter SHA-256 `39c68bb5c98da25eaa466434ba1c6d4a47bedcec580c991f00335627382a3a73` |
| 점수 기반 모델 | `Qwen/Qwen3-Embedding-8B` | revision `1d8ad4ca9b3dd8059ad90a75d4983776a23d44af` |
| 점수 앙상블 | epoch 1~4 LoRA와 각 3출력 회귀 헤드 | 4개 독립 member |
| 제출용 최종 근거 | emitted-score-conditioned A.X DPO LoRA | adapter SHA-256 `887abf9d1bf07693251a17b7a0fb655fe8203fa6945e9c178a38bdc538ded826` |

두 기반 모델의 전체 가중치와 custom LoRA/헤드는 Docker 이미지 안에 포함한다.
컨테이너 시작 시 Hugging Face나 외부 네트워크에서 모델을 내려받지 않는다.

## 3. 데이터와 분리 원칙

### 3.1 대회 데이터

- 학습 글: 2,000개
- 개발 검증 글: 400개
- 예측 축: `content`, `organization`, `expression`
- `average` 점수는 최종 점수 모델의 입력, 목표 또는 출력으로 사용하지 않음

### 3.2 AI-Hub warm start

Qwen3-Embedding 점수 모델은 48,016개 AI-Hub 인간 피드백 레코드로 먼저 학습된
LoRA·회귀 헤드 상태에서 시작한다. 이 상태에는 네 번째 `average` 헤드가 있었지만,
대회 데이터로 계속 학습하기 전에 해당 행을 제거하고 세 평가 축만 유지했다.

### 3.3 합성 근거

OpenAI 생성기로 각 학습 글에 세 개의 근거 후보를 만들어 총 6,000개를 확보했다.
이 후보들은 A.X 근거 생성기의 SFT에 사용되었다. 400개 검증 글의 합성 근거는
훈련이나 선호쌍 생성에 넣지 않았다.

### 3.4 개인정보와 Git 경계

원문 글, 식별자, 개별 근거, 개별 예측, 체크포인트와 로그는 제한 또는 무시 경로에
보관한다. Git에는 설정, 코드, aggregate 지표, 체크섬과 재현 기록만 남긴다.

## 4. 학습 방법

### 4.1 내부 score-blind 근거 생성기

#### SFT 단계

`skt/A.X-4.0-Light`를 6,000개 합성 근거 후보로 LoRA SFT했다.

- 작업: 내용·조직·표현 근거를 한 JSON에서 생성
- 점수 입력: 없음
- LoRA rank/alpha: 32/64
- 최대 입력 길이: 3,072
- 학습률: `2e-5`
- epoch: 2
- completion-only loss
- 수치 형식: float32 기반·LoRA 연산, TF32 허용

#### GRPO 단계

SFT 어댑터에서 점수 비공개 GRPO를 이어서 학습했다.

- train-only 그룹: 1,920
- 그룹당 정책 생성: 4
- 업데이트: 480
- 학습률: `1e-6`
- `beta=0.02`
- `dr_grpo`, reward scaling 없음
- sampling temperature `0.7`, top-p `0.95`
- 축별 근거 최대 192자
- 정책 seed `2026072209`

보상 모델은 `Qwen3.6-35B-A3B-FP8`이었다. `random1` 방식은 각 생성 결과에
다섯 개의 고정 judge 프롬프트 중 하나를 안정적인 해시 규칙으로 배정하고 그
평가를 보상으로 사용한다. 정책 프롬프트와 judge 프롬프트 모두 사람 점수와
합성 후보 점수를 받지 않는다.

최종 점수 회귀 결합 성능을 기준으로 A.X `random1` 어댑터를 선택했다.

### 4.2 Qwen3-Embedding 3축 점수 모델

#### 입력 구성

각 입력은 다음 세 요소로 구성한다.

1. 글쓰기 문항
2. 학생 글
3. 내부 근거 생성기가 만든 내용·조직·표현 근거 JSON

정확한 직렬화 계약은
[`production_r0.py`의 `_score_input`](../../../deployment/src/mal2026_submission/production_r0.py)에
구현되어 있다. tokenizer는 우측 절단을 적용하며 최대 길이는 2,048이다.

#### 모델 구조

Qwen3-Embedding의 마지막 non-padding 토큰 hidden state를 취하고 float32에서
L2 정규화한 뒤, 세 출력을 갖는 선형 회귀 헤드에 입력한다.

수식으로 표현하면 각 축의 연속 예측은 다음과 같다.

```text
h = Qwen3(input)[마지막 non-padding 위치]
z = h / ||h||₂
y = Wz + b,  y ∈ R³
loss = mean((y - target)²)
```

학습 중에는 출력 범위를 강제로 제한하지 않는다. clipping과 정수화는 네 member의
예측을 평균한 뒤에 한 번만 수행한다.

#### 학습 설정

- 초기화: AI-Hub 48,016건 LoRA warm start
- 대회 학습 글: 2,000개
- 목표: 내용·조직·표현의 연속 점수
- LoRA target: Q/K/V/O 및 gate/up/down projection
- LoRA rank/alpha/dropout: 16/32/0.05
- 학습률: `1e-4`
- weight decay: 0.01
- warmup ratio: 0.05
- global batch: 64
- BF16, TF32
- seed: `2026072601`
- 12 epoch, epoch마다 LoRA와 회귀 헤드 저장

### 4.3 epoch 1~4 예측 앙상블

제출 시 각 epoch member를 독립적으로 활성화하여 같은 입력을 네 번 처리한다.
member별로 LoRA와 회귀 헤드가 함께 바뀐다.

축 `a`에 대한 연속 앙상블 점수는 다음과 같다.

```text
s_a = (s_a,epoch1 + s_a,epoch2 + s_a,epoch3 + s_a,epoch4) / 4
```

그 뒤 최종 정수 점수는 다음 규칙으로 계산한다.

```text
c_a = min(5, max(1, s_a))
integer_a = floor(c_a + 0.5)
```

검증 데이터에 맞춘 member 가중치, 축별 threshold, affine calibration 또는 추가
후처리는 사용하지 않는다.

### 4.4 제출용 최종 근거 DPO

점수 모델의 입력에 사용한 짧은 근거는 내부 표현으로 취급한다. 사용자에게 반환할
근거는 별도의 A.X DPO 어댑터가 생성한다.

최종 근거 프롬프트에는 다음 정보만 들어간다.

- 글쓰기 문항
- 학생 글
- R0이 방금 산출한 내용·조직·표현 정수 점수

사람 정답 점수나 reference score는 제공하지 않는다.

DPO 학습에서는 각 train-only 입력에 후보 네 개를 생성하고 고정 Qwen Q4 judge의
12-cell 합계로 최선과 최악 후보를 고른다. 점수 차이가 없는 그룹은 제외한다.

- 생성 그룹: 6,000
- 생성 후보: 24,000
- 비동점 선호쌍: 2,770
- 학습기: TRL `DPOTrainer`
- loss: sigmoid DPO
- `beta=0.1`
- 학습률: `1e-6`
- epoch: 1
- global gradient accumulation: 16
- DPO seed: `2026072707`

## 5. 추론 절차

### 5.1 입력 파싱

서버는 OpenAI 호환 `messages`에서 `[prompt_text]`와 `[essay_text]` 구간을 추출한다.
대회 평가기는 전체 지시문과 두 구간을 하나의 `user` 메시지로 보낼 수 있다.

### 5.2 내부 근거 생성

A.X 기반 모델에 `rank2_ax4_random1` LoRA를 활성화한다.

- temperature: 0.0
- top-p: 1.0
- 기본 seed: 42
- 최대 생성: 512 tokens
- 출력: 내용·조직·표현의 rationale-only JSON

### 5.3 점수 앙상블

내부 근거와 원 입력을 Qwen3 tokenizer로 최대 2,048 토큰까지 인코딩한다. epoch
1~4 adapter/head를 차례로 활성화하고 각각 세 축 연속 점수를 구한다. 네 예측을
평균하고 `[1, 5]`로 제한한 뒤 half-up 방식으로 정수화한다.

### 5.4 최종 근거 생성

A.X 기반 모델에서 final DPO LoRA를 활성화하고 원 입력과 방금 계산한 세 정수
점수를 조건으로 최종 한국어 근거를 생성한다.

- temperature: 0.0
- top-p: 1.0
- 기본 seed: 42
- 최대 생성: 512 tokens
- 축별 근거 길이 계약: 1~384자

### 5.5 응답 직렬화

최종 응답은 다음 의미 구조를 갖는 하나의 compact JSON 객체다.

```json
{
  "content": {"score": 1, "rationale": "한국어 근거"},
  "organization": {"score": 1, "rationale": "한국어 근거"},
  "expression": {"score": 1, "rationale": "한국어 근거"}
}
```

실제 점수는 각 축 1~5의 정수다. Markdown fence나 설명문을 JSON 앞뒤에 붙이지
않는다.

## 6. 서빙과 제출 계약

- 실행: 별도 명령 인자 없는 컨테이너 시작
- bind: `0.0.0.0:8000`
- endpoint:
  - `GET /health`
  - `GET /v1/models`
  - `POST /v1/chat/completions`
- 기반 이미지: immutable `vllm/vllm-openai` digest
- 모델 로딩: 컨테이너 내부 파일만 사용
- rationale 추론: vLLM LoRA serving
- score 추론: Transformers + PEFT
- score 모델과 rationale 모델은 한 visible GPU에서 순차적으로 공존

첫 이미지 `20260731-001` 이후의 `20260731-002`는 주최 측의 문자열 비인식
중괄호 파서에 대응해 rationale 내부 중괄호 치환과 HTTP 경계 재직렬화를 추가했다.
모델 가중치, 프롬프트, 점수 앙상블과 최종 DPO 방법론은 바꾸지 않았다.

## 7. 선택 근거

최종 R0 조합이 선택된 이유는 다음과 같다.

1. A.X `random1`은 상위 근거 후보 중 점수 회귀 macro RMSE가 가장 낮았다.
2. Qwen3의 AI-Hub warm start는 공개 base 직접 초기화보다 현저히 안정적이었다.
3. epoch 1~4 예측 평균은 최선 단일 checkpoint보다 RMSE와 Spearman이 모두 좋았다.
4. 검증 label로 ensemble 가중치나 threshold를 적합하지 않았다.
5. DPO 근거 모델은 고정 검증에서 가장 높은 judge macro를 기록했다.
6. 전체 파이프라인이 모델 포함 Docker GPU/API 스모크와 공개 registry 검증을 통과했다.

## 8. 한계

- 점수 및 근거 지표는 반복 노출된 400개 개발 검증 집합의 결과다.
- LLM-as-judge 점수는 인간의 설명 품질 평가를 대체하지 않는다.
- 내부 score-blind 근거와 최종 DPO 근거는 목적과 프롬프트가 서로 다르다.
- 점수 지표는 최종 DPO 근거를 붙이기 전 고정 점수 앙상블의 지표다.
- 실제 L40S에서의 커널 호환성과 지연 시간은 첫 제출 전에 직접 측정하지 못했다.
- Docker 공개 검증은 저장소로 확인되지만 대회 플랫폼의 제출 이벤트는 별도 기록이 없다.
